**Goal:** Make ordinary transitions independent of retained history while preserving full-State compatibility, atomic ownership fences, exact quotas, replay and protected storage.

**Architecture:** Introduce an opt-in, separately versioned transactional record-access capability. Both the snapshot reference and PostgreSQL adapters run the same pure transition planner; PostgreSQL reads verified paths from one authenticated state tree with schema-defined map ordering and commits a validated patch and projections under the namespace fence. A bounded connection pool permits independent namespaces to progress concurrently while each namespace retains one logical owner and revision order.

## Representation decision to review before production API/schema edits

PB-04.proposal.md:143-153 requires review of a concrete representation/patch prototype and quota proof before migration or runner/Storage API changes. Existing rooted examples explicitly do not approve production integration. This plan proposes the following implementation; review must resolve the integrity boundary before Task 2.

### Canonical authenticated tree

Use one namespace header pointing to an immutable authenticated JSON tree. Physical map order follows the Rust schema's key type; canonical serialization order is a separate full-reader concern. Arrays use ordered sequence trees carrying element counts, allowing append and indexed access without reading old receipts. Scalars and record payloads are canonical bytes. A node reference binds its full row identity (defined under Protection), content digest, node kind, comparator tag, subtree count and exact canonical byte contribution. Internal references and comparator/balance metadata are verified before a node can establish membership, a range boundary, or absence. Missing referenced SQL rows are corruption, never absence. No cache survives a transaction.

The format-1 schema certificate assigns these map comparator tags by logical container path, never by guessing whether a string looks numeric:

| Container | Comparator and accepted key encoding |
| --- | --- |
| `indexes.ready[scope]`, `indexes.events[correlation]`, `indexes.receipts[run]`, `indexes.all_receipts`, `catalog_history`, `catalog_history_at_ms` | `U64`: numeric order; canonical unsigned decimal keys, checked through `u64::MAX` |
| `indexes.due` | `I64`: signed numeric order; canonical signed decimal keys, checked through `i64::MIN..=i64::MAX` |
| String-keyed object maps only, including `catalog_history[revision]`, scope/cursor and effect-kind maps | `String`: Rust string order, matching their `BTreeMap<String, _>` types |
| String sets such as effect queues and completion-ready | Ordered sequence/set nodes preserving `BTreeSet<String>` order |
| Receipt vectors and other arrays | Sequence position order; never lexical sorting of element values |

The certificate must enumerate all State/index fields, including `keyed_admissions`; assert U64 tags for both catalog-history containers and String for their string-keyed nested activation maps in `tree_schema_certificate_matches_state`; a type/comparator mismatch, duplicate logical key, noncanonical numeric spelling (`09`, `+9`, `-0`) or out-of-range numeric key refuses import/patch. Numeric maps retain both their typed comparison value and exact canonical JSON key spelling. Comparator tags and key spellings are authenticated. `Tree::range` and first-key selection use that comparator: ready sequence 9 precedes 10; timer -10 precedes -2 and 0; event/receipt `after_sequence=9` selects 10 next. Verify predecessor/successor and exhausted-range boundaries from the same root rather than scanning lexical order or consulting a SQL projection.

`Tree::materialize` walks all nodes and reconstructs the full State. Before canonical byte comparison/output it recursively re-sorts object keys by the canonical serializer's string order, including numeric map keys (so serialized `"10"` precedes `"9"`). It preserves array/set sequence order. Full materialization may be O(S + H log H); ordinary numeric selection remains a tree seek plus the returned entries. The canonical-byte test must call the existing `canonical_bytes(&full_state)` oracle rather than serialize physical traversal order.

The prototype's AVL object implementation is an algorithm reference, not code approved for promotion: it treats arrays as opaque leaves, lacks deletion, omits current `keyed_admissions` from its schema certificate and has no production protection or ownership. Implement typed comparators, sequence append/indexing and object deletion with independent tests before using the tree as a storage format.

Exact byte proof is inductive: scalar contribution is canonical UTF-8 length; object contribution is 2 + sum(canonical key bytes + 1 + child bytes) + max(count - 1, 0); array contribution is 2 + sum(child bytes) + max(count - 1, 0). Here canonical key bytes include JSON quotes/escaping. The object sum and comma count are invariant under permutation: numeric physical order changes neither key/value pair lengths nor entry count, so it preserves the exact canonical length even when serialization order differs. Arrays are not permuted. Internal balancing nodes contribute no logical JSON delimiters. Recompute changed ancestors with checked arithmetic and authenticate their summaries. The logical State root includes artifacts even though artifact payloads remain deduplicated. Quotas include `receipts.len() + keyed_admissions.len()` and every queued destination whose run is absent. Count deltas derive from validated before/after records, never estimates. Test computed length against `canonical_bytes(&full_state).len()` and canonical materialized bytes against the reference after every step, including numeric order permutations, insertion/deletion/rebalancing and receipt-offset shifts.

The ordinary node trigger rejects UPDATE, DELETE and TRUNCATE. The precise INSERT conflict and administrative DELETE rules are defined under Protection; a digest alone is not a row address. Initial implementation may retain unreachable immutable nodes outside explicit GC/rotation; record physical growth, and do not claim a physical-storage bound. Logical GC preserves existing replay/disposal semantics. Production activation must explicitly disclose this physical retention limit.

### One canonical transition planner

Create `planner::StateAccess`, with fallible point reads, ordered range reads, count/byte reads and patch writes. The range interface carries the schema comparator, inclusive/exclusive bounds and a requested result limit; it returns verified items plus authenticated continuation/exhaustion evidence. A `StateAccess` implementation must return complete results for that requested page/range or an explicit bound error. It cannot synthesize empty collections for omitted state. A working-set certificate is the verified record/range read set under one root, owner, incarnation and revision. Writes carry their expected prior digest or proven absence.

Extract transition logic from Engine closures into `planner::plan(access: &mut dyn StateAccess, request: &TransitionRequest) -> Result<TransitionResult>`. `TransitionRequest` owns the existing method arguments, and `TransitionResult` returns the existing method result plus a validated patch. Supported variants cover event admission, root/keyed admission, run advance, fanout, cancellation, effect selection, effect results, deadline/completion processing and the ready/effect turn. No host object is accepted by the planner. Administrative artifact/activation/replay/retention mutations initially use the explicit full-reference path.

The reference adapter uses a complete State and the same planner, preserving an independently materialized oracle. Runtime index mutations are extracted alongside source mutations: planner code must not query a SQL projection to skip an authoritative source read. Ready/effect/timer/event/receipt selection uses the typed comparator table above, reads authenticated index paths and verifies selected source records. Bound the tree work by O((W + R) log H + R) visited nodes for W touched records and R selected entries/boundary proofs, plus actual accessed payload/key bytes; do not hide a queue scan or canonical full re-sort in a numeric first/range operation. Receipt compaction may touch O(H) shifted offsets and remains an explicit administrative full-reference operation. Full CAS/import derives and verifies indexes against source before publishing a certified root. An inconsistent arbitrary full CAS is rejected atomically, not silently repaired or accepted as a certificate.

Do not implement an independent fast-event algorithm or pass a partial State to MemoryStorage. Every required PB-02 timed operation must exercise the incremental capability; report full-fallback counters and require zero fallbacks in those windows. Explicit O(S) administrative operations and public full-load/full-CAS compatibility remain permitted.

### Versioned capability and publication

Add a default-unsupported `Storage::transition_v1(namespace, owner, request, config)` returning an explicit `Unsupported` or completed transition result. Add a non-mutating, default-unsupported support query alongside `transition_v1`, scoped to namespace/representation; decorators must forward both. Snapshot storage continues to use full load/CAS, invoking the shared planner over a complete State. PostgreSQL obtains a pool slot, locks the namespace header, verifies owner/incarnation/revision/representation, and evaluates the planner against verified tree nodes. Before commit it validates the patch, replay/receipt retention, exact quotas and expected old values, then writes nodes, derived index/public/catalog changes and the new root/revision together. Failure publishes none of them. No public API returns the certified working set as a State.

Migration 0005 adds an explicit representation selector, typed node-format certificate and format-3 writer guard; it does not repurpose the old envelope. Snapshot namespaces remain writer format 2; rooted namespaces require writer format 3. The migration replaces the fixed `writer_format=2` CHECK with selector/format consistency and rewrites both namespace and catalog guards as specified below. A format-2 session cannot reset a rooted namespace to format 2 or mutate any of its projections. Fresh old constructors reject the migration checksum/version; already-open old writers fail the namespace writer trigger. Old readers must refuse a rooted selector rather than decode a stale old snapshot: clear the legacy payload on selector switch, subject to a new exclusive envelope constraint. New full readers reconstruct and verify the complete State from the selected representation. Full CAS performs existing complete retention/artifact/receipt validation, rebuilds the root, and atomically updates projections.

### Parallel writers with one owner

Provide an opt-in pool constructor accepting an owner `Client` and 1–4 worker `Client`s, preserving caller-controlled TLS. Existing constructors keep the snapshot-compatible path. The owner connection holds the existing session namespace lock. Workers never acquire that original lock on behalf of the owner. Add a second namespace advisory handover lock using PostgreSQL's disjoint two-int advisory-key space (`objsubid=2`), with a domain-separated namespace hash; the existing one-bigint owner lock uses `objsubid=1`. A hash collision may serialize extra namespaces, never grant ownership: predicates also compare the full namespace/owner/incarnation. All lock probes match the current database OID, key halves, `objsubid`, PID, mode and `granted`, avoiding cross-database/key-space false positives.

Lock order is original owner session lock when required, then handover lock, then namespace row. Every rooted incremental/full read takes the shared handover transaction lock before reading its root, and every worker mutation takes it shared before `FOR UPDATE` on the namespace row. Acquisition, release, migration, rotation and GC take the handover lock exclusive before the row lock. This excludes readers during deletion/selector changes and avoids a row-lock/handover deadlock. Acquisition/release remain owner-connection operations. A replacement owner first obtains the original session lock, then the exclusive handover lock before incrementing incarnation; it cannot overtake an old in-flight commit. Release drains shared holders, clears ownership under its own PID/incarnation fence, commits and then unlocks the original session lock.

#### Exact format-3 worker fence and its authority change

Today `0004_catalog_inspection.sql:check_catalog_writer` and `commit_state` require `owner_backend_pid=pg_backend_pid()`; that predicate is intentionally retained for format-2 snapshot writes and for owner-only lifecycle operations. It cannot authorize a format-3 worker on another backend. Migration 0005 explicitly replaces it for format-3 transition/full-CAS publication with a common SQL guard, used by namespace, catalog and new node write triggers:

1. Transaction-local settings name the exact namespace, writer format `3`, owner token, incarnation and expected base revision. Missing, malformed or stale settings refuse.
2. The namespace is rooted/format 3, has a non-null owner, and its locked header matches that owner/incarnation/base revision. Final root publication checks OLD.revision against the base and NEW.revision=OLD.revision+1; projection count-trigger updates retain the base revision and all existing identity/count/catalog-completeness constraints.
3. The calling backend PID has a granted `ShareLock` on this namespace's handover advisory key. Merely setting the GUCs, holding the original owner lock or presenting a PID does not qualify a worker.
4. The recorded `owner_backend_pid` still has a granted `ExclusiveLock` on the original namespace session advisory key. This verifies the owner's lock, rather than erroneously requiring the worker to own it. All four checks run before planning and are re-evaluated by each fenced node/catalog/namespace write trigger, including final root publication; they are not cached transaction-start authorization. The shared handover lock and namespace row lock remain held until commit.

`check_catalog_writer` dispatches on the stored namespace format, not a client-supplied proposed format. Its ordinary format-2 branch keeps the current PID check. Format-3 node INSERT, catalog INSERT/UPDATE/DELETE, derived projection/count updates and root publication accept either all four worker conditions above OR the complete administrative predicate below. The exclusive administrative lock does not count as a ShareLock; the alternatives are explicit, never a relaxed lock-mode comparison. `check_namespace_writer` rejects old-format writes even if they propose changing writer_format/selector and applies the same two-branch guard to rooted State publication. Node INSERT additionally validates immutable row identity/envelope metadata; ordinary node UPDATE/DELETE/TRUNCATE refuses regardless of GUCs. Native/public projection writers use the same qualified transaction. Publish the new root/revision last, after node/projection changes; final catalog completeness and actual/expected counts still apply. Full-CAS on a rooted namespace uses this fence and complete validation, without the legacy same-PID CAS check. Owner release retains its own `owner_backend_pid=pg_backend_pid()` predicate and requires exclusive handover, never the worker branch.

The administrative predicate requires all of: exact transaction-local namespace, writer format `3`, owner, incarnation and expected base revision; an explicit allowlisted administrative operation (`bootstrap`, `acquire`, `release`, `migrate_v1`, `rotate_v1` or `gc_v1`); the calling PID holding both the original owner session ExclusiveLock and the handover transaction ExclusiveLock; and `owner_backend_pid=pg_backend_pid()` with matching owner/incarnation in the locked header. The same database/key-space/granted checks apply as in the worker predicate. A transaction declaring a mismatched operation, arbitrary operation string, missing setting or stale context refuses. Checks are re-evaluated on every fenced write. Merely holding exclusive handover or setting the operation GUC never grants administrative authority.

Operations also restrict the permitted writes. `migrate_v1` and `rotate_v1` may INSERT nodes, update catalog/projection envelopes and publish the root under this administrative predicate; `gc_v1` may delete only verified-unreachable nodes under the deletion rule below. Administrative node UPDATE/TRUNCATE still refuses. `acquire` and `release` are ownership-header operations only; bootstrap may insert its initial nodes/projections/root after establishing the new header and owner context. The explicit acquisition exception validates the old header/base revision under both caller-owned locks before replacing the recorded PID/token/incarnation; it does not authorize node or catalog writes using the old owner context. Fresh header creation likewise requires both locks before assigning its PID. Ordinary workers cannot change owner/incarnation or select an administrative branch merely by setting an operation GUC.

The `migrate_v1` guard explicitly accepts a stored format-2 snapshot header while building format-3 nodes and catalog/projection data: it requires the current format-2 owner PID/token/incarnation/base revision, writer setting `3`, both exclusive locks and the migration operation. This is a narrowly named administrative exception to stored-format dispatch, including catalog count-trigger header updates; ordinary format-2 writers keep their existing fence. It validates the complete old state and new tree before changing selector/format together at final root publication. All administrative data writes/deletions precede that publication and retain the base revision; the publication checks OLD.revision=base and NEW.revision=base+1. Pure acquire/release keep the existing state revision unchanged. Migration rollback restores the entire format-2 namespace, and rotation rollback restores all old envelopes and rows.

This changes connection authority: for format 3 a trusted database-role backend meeting the shared-lock and owner-context predicate can publish on behalf of the owner. Same-PID isolation is no longer claimed for those writes. Advisory locks and GUCs are concurrency fences, not authentication against hostile SQL clients with the same role; application authorization remains outside the transaction as before. Review acceptance must explicitly cover this relaxation, the unchanged format-2 fence, lifecycle isolation and the negative tests in Task 4.

If the owner lock is gone at initial validation, refuse before planning. If the owner connection disappears before any later fenced write, that write rechecks condition 4 and aborts the transaction, rolling back even nodes/projections written earlier. Only loss after the last successful fenced write (normally final root publication) and before COMMIT can let an old transaction finish without another owner-lock check. It still holds shared handover, so replacement/release cannot pass exclusive handover until it ends. Thus an old incarnation may commit before replacement publishes, never after it. There is no new deferred commit-time owner-lock check. On a lost commit reply, reload the committed revision/receipt under a fresh verified context; never blindly replay an external effect.

Pool admission is FIFO with at most 64 waiting requests and at most the configured number of workers; saturation returns an explicit overload error. The FIFO is process-local backpressure, not accepted durable work. It must not automatically retry mutations or reset producer retries. Connections do not share a mutex for database I/O. Per-namespace serialization under the root is intentional; independent namespaces must progress while another worker is paused.

Pool database workers and owner-client operations run on dedicated OS threads. Before any synchronous client call on each thread, a test asserts `tokio::runtime::Handle::try_current().is_err()`; the pool constructor returns an explicit error when invoked from a thread already entered into a Tokio runtime, before any client I/O. Runtime-context refusal returns the supplied clients to the caller in a recoverable error payload, rather than dropping synchronous clients inside that entered runtime; document that the caller must arrange safe disposal on an OS thread. The synchronous `postgres` client's own internal runtime is expected. Task 4 adds a direct Tokio dependency with the runtime/test features needed for the guard; keep Cargo.lock updated. Test a normal constructor, each worker's execution context, and constructor refusal inside an entered runtime.

### Protection and migration

#### Node identity, AAD and conflict verification

Define the node-row primary key as `(namespace, logical_path, node_kind, node_format, key_slot, digest)`. `logical_path` is an unambiguous typed component encoding: map/scalar values use their full logical State path; all internal balancing nodes for a map/sequence use that logical container's path, never a physical left/right branch path. Rebalancing therefore does not rename unrelated descendant rows. Array positions are logical components where applicable; receipt deletion/offset shifts may legitimately require rebuilding O(H) affected paths on the administrative path. The schema fixes `node_kind`, comparator domain and format for each path.

`key_slot` is non-null: the empty string denotes plaintext; protected rows use the exact nonempty key ID (as already required by ProtectionKeyring). Envelope CHECKs enforce that plaintext has bytes only and protected rows have that key ID, one random 24-byte nonce and ciphertext only. The plaintext node encoding is canonical and includes node kind/format/comparator, exact logical byte/count metadata and complete child references. `digest=SHA256(canonical node plaintext)`; it is not a ciphertext digest. A `NodeRef` carries the complete row tuple and authenticated summaries. Parent plaintext commits to complete child addresses, including key slots. All tuple/path/AAD encodings are length-delimited or canonical tuples, never ambiguous string concatenations.

Protect each node with XChaCha20-Poly1305 using a fresh random nonce and AAD `(new node domain, namespace, logical_path, node_kind, node_format, key_slot, digest)`. Verify AAD, plaintext digest, schema/comparator and metadata after decryption. Deduplication is only within that full row identity: equal plaintext at different logical paths, namespaces, formats or key IDs may share a plaintext digest but has distinct rows/envelopes. No global digest-only dedup claim applies to these node rows.

On INSERT conflict, re-read the exact primary-key row, validate its envelope, decrypt with its recorded key/AAD, recompute the canonical plaintext digest and summaries, and compare canonical plaintext bytes to the proposed node. In plaintext mode compare validated canonical plaintext directly. Equal plaintext reuses the existing envelope despite a different proposed random nonce/ciphertext; a missing key, invalid envelope, hash/metadata mismatch or unequal plaintext aborts the entire transaction. Never compare randomized ciphertext for equality, skip verification on a digest match or overwrite a conflicting immutable row.

Protect the root manifest using a distinct root domain, namespace, namespace revision, representation/node format, active key ID, complete root reference and exact counters. Owner and owner incarnation are deliberately excluded from root AAD; row/advisory-lock checks fence ownership. Acquisition still verifies the current root with available referenced keys as required by the reader, but a pure ownership change leaves namespace revision, root bytes and key slots unchanged and needs no reseal/new active-key ciphertext. Test replacement acquire with the old root-decryption key present and a different configured active key, then verify incarnation advances and the envelope is byte-identical; missing required root keys still refuse.

#### Migration, rotation and deletion

`migrate_namespace_v1` runs under the exclusive administrative guard and rejects active runs/unresolved effects and pending work. It verifies the old complete state/artifacts, builds and audits the new root, then switches selector atomically. Fresh namespaces may start in the new representation. Crash before switch leaves the old snapshot usable; crash after commit leaves a complete new root. Reversal, if exposed, must materialize the latest root; an obsolete retained snapshot is not rollback.

`reencrypt_namespace` remains one explicit atomic administrative operation, under exclusive handover so it excludes all full/incremental readers and writers. Walk and verify every reachable node, artifact and protected catalog/auxiliary value. Rebuild bottom-up under the active key: child key slots change parent plaintext references and thus may change parent digests. Insert new-key rows alongside old-key rows using the full primary key and plaintext conflict rule; same-key rotation reuses a verified existing envelope where plaintext is identical. Seal the root and other retained protected values under the active key. Verify the complete reconstructed State and exact quotas before publication.

The node trigger's only DELETE exception is a fenced administrative GC/rotation operation. UPDATE and TRUNCATE remain prohibited. Before deletion, verify the proposed final retained root and materialize its full reachable-address set while holding exclusive handover plus the namespace row lock. Delete only namespace rows outside that set; ordinary workers with a shared lock cannot invoke this exception. Rotation reseals current artifact/catalog envelopes and deletes all prior-key node rows unreachable from the verified proposed root, including rows unreachable before rotation, then publishes that root last in the same transaction. Exclusive handover excludes readers while the old header temporarily references rows being retired; rollback restores those rows. Its final checks require every retained reference and protected value for this namespace to use the active key and no old-key node rows to remain. A corrupt unreachable old-key envelope may be discarded only after proven unreachable from the fully verified retained root; reachable corruption/missing keys refuse rotation. Failure rolls back root, inserts, reseals and deletion together.

Success releases old-key requirements for live reads/writes of this namespace, including later recreation of previously seen nodes. It does not authorize removing a key still required by another namespace, other stored values or encrypted backups; scan that scope before key removal. No old roots are retained as readable history by this format. If that policy changes, retained-root reachability/key checks must expand before keys can be retired. Ordinary patch commits do not imply rotation. Current full-CAS validation and disposal tombstones remain authoritative across the switch.

Tests must enumerate: equal plaintext/digest at two paths has distinct valid rows and substitution fails; repeated insertion at the same path/key with different random nonces succeeds by plaintext comparison; active-key rotation can remove old-key rows and read/recreate nodes with only the active key, while interruption retains the entire old state/key requirement.

### Integrity policy requiring a decision

An O(W log H) transaction cannot rescan O(H) unrelated history. The proposal is: verify every selected node/path freshly, prevent ordinary immutable-node edits, authenticate roots and references, and detect unrelated retained corruption on full load/audit and migration/rotation. Deliberate superuser corruption of an untouched node can remain undetected until that node is read. Existing protected snapshot loads authenticate all snapshot bytes on every operation. This is an observable timing-of-detection difference, not a claim of identical corruption detection. The owner/reviewer must accept this explicit boundary or require a different design; no production implementation should silently choose it.
