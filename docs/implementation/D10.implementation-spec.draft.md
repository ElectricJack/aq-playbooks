# D10 authenticated bounded transitions — implementation specification

## Goal and boundaries

Complete the approved D10 outcomes on the current repository, starting at `c0d0376`: ordinary transitions use a shared pure planner and authenticated bounded reads, publish all state and projections atomically, preserve exact quotas and complete-State compatibility, and allow independent namespaces to progress on bounded worker connections. Protected migration, atomic rotation, ownership fencing, replay, and the complete PB-02 matrix are required delivery, not optional follow-ups.

This is an implementation spec for Jack's review. Its approval permits the normal ingestion pipeline to derive work. This authoring task files no implementation tasks and makes no production changes. The approved design's execution-skill directive applies to implementing its tasks, not to this document-authoring task. No additional adversarial-agent round is required by this spec.

Defaults are fixed here: opt-in authenticated representation `tree_v1`; writer format 3 with an explicit representation discriminator; additive migration 0006; a new typed `Storage::transition_v2` capability beside the existing closure-based v1; one owner connection plus 1–4 dedicated worker connections (default 2 for the convenience constructor), FIFO with 64 waiting requests maximum; no automatic mutation retries; transaction-local verification caches only. Existing constructors continue creating snapshot namespaces; record constructors continue creating legacy record namespaces. No automatic data conversion, old-format downgrade, or active-run migration is introduced. Administrative full operations may remain O(S).

Rust 2024 and the committed Cargo.lock remain authoritative; all builds/tests use `--locked`. Each repository builds alone. No edits to `docs/specs/*`, aq-server, the host catalog contract, or external adapters belong here. No unresolved-work eviction, retry reset, quota widening, or 500-agent claim. D11 vendoring, J3 deployed measurement, and MS4 settlement remain existing downstream work, not duplicate tasks or prerequisites of this spec.

### C1 — owned requests and one canonical planner

Create runner `src/planner/{mod,access,reference}.rs` (a directory module instead of the design's single planner.rs, to separate access and reference ownership). `StateAccess` exposes fallible typed point reads, typed ordered range pages, verified counts/byte summaries, and staged put/remove/append. A page carries comparator, inclusive/exclusive bounds, result limit, continuation or exhaustion evidence. An implementation returns the complete requested page or an explicit bound error; missing proof nodes are corruption, never empty collections. The certificate binds root, namespace, owner, incarnation and base revision; every write carries expected old digest or verified absence. Reads see staged writes in the same plan.

`planner::TransitionRequest` owns its data and is Send: event/root/keyed admission, advance, fanout, cancel, effect selection, post-authorization state update, effect result, deadline processing, completion processing, and ready/effect turn. Preserve IDs, arguments, result types, no-op revision behavior and errors of existing Engine methods. `plan(&mut dyn StateAccess, &TransitionRequest, &EngineConfig) -> Result<TransitionResult>` returns a typed result and validated patch, never a host object or caller closure. A request evaluates once; errors do not cause a hidden retry. Keep this API independent of postgres and Tokio.

Add `Storage::transition_v2(namespace, owner, request, config)` and `transition_v2_support(namespace)` with default Unsupported/false. Add public result/outcome types without modifying existing v1 types. Retain v1 for callers that already implement/use it; rooted namespaces report v1 unsupported before executing a closure. The new Engine uses v2, or runs the same planner on a complete ReferenceAccess loaded through Storage and commits through complete CAS. It does not use legacy v1 as a substitute for the typed planner. This keeps custom backends compiling and ensures both new execution paths share the planner. Administrative install/activation/replay/retention mutations remain explicit full-reference operations. Existing legacy v1 callbacks, if directly invoked, keep their published contract.

Move source mutation and associated index changes together, including `indexes::refresh_run`, `refresh_intent`, event/activation indexing, receipts and dirty tracking. Range selection reproduces `RuntimeIndexes::query` limits/ties, numeric order, scope and item cursors, wraparound and effect/ready turn. Verify selected source records against authenticated index entries. User payload objects may remain canonical opaque record bytes, charged as accessed payload; unbounded runtime membership maps/sets and sequence collections must be navigable rather than silently copied as one leaf. Failure/cancellation/deadline branches must not scan all historical runs. A truly large requested fanout can cost proportionally to returned/touched work; that cost is explicit W/R, not hidden history work.

Keep authorization calls, dispatch, cancellation host calls and reconciliation in Engine orchestration before/after committed planner requests. Host-returned results become owned inputs to a subsequent transition. Full-State reference serialization remains the independent canonical oracle; test return values/errors, full states and revisions after every step, including no-op/refused transitions.

### C2 — authenticated tree and exact accounting

Create postgres `src/incremental/{mod,schema,tree,accounting}.rs`. Use immutable balanced object trees and ordered sequence trees, initially AVL for maps and count-indexed balanced sequences. No production promotion of `examples/rooted/tree.rs` without deletion, sequences, complete schema, protection and fences. Node references bind full identity, kind/format, comparator, digest, count and exact canonical byte contribution. All proof metadata used to establish membership, ordering or absence is authenticated and checked, including children, balance, boundary summaries and shape. Transaction-local memoization is bounded; reaching a fetch/byte limit returns an explicit error with no patch. No cache survives commit/rollback, ownership change or selector switch.

Node key: `(namespace, logical_path, node_kind, node_format, key_slot, digest)`. Paths are canonical typed components, never concatenated ambiguous strings. Internal balancing nodes use the logical container path, not physical left/right positions, so rebalance does not rename unrelated descendants. Scalar/record paths include their logical key; sequence element paths preserve logical positions. `node_format=1`; `key_slot=''` is plaintext, otherwise an exact key ID. Plaintext encoding commits to all complete child addresses and summaries; digest is SHA-256 of canonical plaintext, not ciphertext.

The schema certificate is exhaustive over serialized State, RuntimeIndexes and RetentionState, including defaults and nested fields. Serde-skipped execution hints such as `protection_available` and dirty sets are explicitly excluded. Classify containers from Rust types, not numeric-looking strings:

| Containers | Comparator/representation |
|---|---|
| `indexes.ready[scope]`, `indexes.events[correlation]`, `indexes.receipts[run]`, `indexes.all_receipts`, `catalog_history`, `catalog_history_at_ms` | U64 canonical unsigned decimal through u64::MAX |
| `indexes.due` | I64 canonical signed decimal through both i64 limits |
| String-keyed maps, including `catalog_history[revision]` activation maps, effect/scope/cursor maps | Rust String order |
| String sets, including completion-ready/effect sets | Ordered set/sequence preserving BTreeSet order |
| Receipts, disposal vectors and arrays | Position order, never lexical value sorting |

Reject wrong comparator/path/kind, duplicate logical identities, `09`, `+9`, `-0`, and overflow. Keep canonical key spelling alongside typed ordering. Numeric selection uses seeks: 9 before 10, -10 before -2, exclusive after-9 selects 10; no lexical scan/re-sort in ordinary selection. Full materialization recursively canonicalizes object keys by the existing serializer's String order (serialized "10" before "9") while preserving array/set order. Verify bytes with `aq_playbooks_model::canonical_bytes(&full_state)`, not physical traversal serialization.

Exact byte induction: scalar = canonical UTF-8 length; object = `2 + Σ(key_json_bytes + 1 + child_bytes) + max(count-1,0)`; array = `2 + Σ(child_bytes) + max(count-1,0)`. Key bytes include quotes/escaping. Balancing nodes add no logical punctuation. Object order does not change the sum; array order is retained. All additions/subtractions are checked and affected ancestors recomputed. The logical root accounts for artifacts even if payload storage is deduplicated. Count quotas are runs, events, receipts **plus keyed-admission receipts**, and each destination whose run is absent. Deltas come only from verified before/after records. Full-root totals must equal full canonical State bytes and `quota_counts` after each test mutation. Receipt compaction can shift O(H) offsets and stays administrative; account for every shift and digit-width change.

`Tree::read/range/apply/materialize` must support an in-memory node-store implementation for ordinary deterministic tests, plus a transaction-backed store for PostgreSQL. The same production tree/planner run in both. The expected work bound is `O((W+R) log(H+1) + R)` visited nodes plus actual accessed key/payload bytes; R includes selection and boundary proofs. Full materialization is allowed O(S + H log H).

### C3 — additive representation and atomic publication

Append `migrations/0006_incremental_state.sql` and register it in MIGRATIONS. Do not modify checksums of 0001–0005. Add `representation` with exclusive envelope consistency:

| Selector | Writer format | Authoritative payload |
|---|---|---|
| `snapshot_v2` | 2 | Existing plain/protected snapshot and verified artifact storage |
| `records_v0` | 3 | Existing plaintext state_header/state_accounting/state_records |

Migration 6 labels existing rows by their actual old format and checks envelope consistency; it does not migrate logical data. Preserve legacy readers/writers for rows that remain in their old representation. Extend old-binary tests to the actual c0d0376 record writer as well as the snapshot writer. Public queries from old binaries are not a route to mutation authority.

Every rooted transition: acquire a pool permit and shared handover, lock header, validate fence/root/certificate, run planner, validate read/write expectations, replay retention and all quotas, then insert immutable nodes and apply projection/catalog/public deltas, publish root/revision last, commit. Rooted full CAS follows the same worker fence with complete before/after validation. Artifact removal/disposal and keyed-receipt validation remain in `retention::verify_artifact_removals`, postgres retention verification, and `admission::verify_receipt_retention`. Quota refusal leaves nodes, projections, counters and revision unchanged. No-op requests leave the revision unchanged.

Derive runtime/public projection deltas from verified touched source/index records with the existing sanitizers; retain the Stage A full-State generators as reference oracles. Do not call full `native_delta(previous,next)`/`public_delta(previous,next)` on ordinary bounded transitions. Maintain runtime_index, inspection_rows, current catalog metadata revision/projected revision, and actual/expected catalog counts atomically. No source absence can be inferred from SQL projection rows. If projection drift affects a requested result, fail closed or repair from verified source within the same qualified transaction; never silently invent an empty authoritative result.

Full import/CAS verifies source/index consistency before certifying a root. Build derived membership/index expectations from source and compare while preserving valid scheduling history/cursors; `indexes::rebuild` alone is not a validator because it reconstructs queue order and mutates State. Reject inconsistent caller-supplied indexes atomically, never silently repair arbitrary input. Preserve valid fairness cursors and receipt offsets. An explicitly uninitialized compatibility State can enter through an explicit normalization step before CAS, using the existing reference behavior; a rooted certificate is always initialized and consistent. Rooted `load` reconstructs and verifies the entire State. Ordinary rooted transactions never return a partial State to MemoryStorage or public callers.

### C4 — exact fences and handover

Retain the original owner session advisory lock (`objsubid=1`, one bigint) and add a domain-separated namespace handover lock using PostgreSQL's two-int key space (`objsubid=2`). Probe exact current database OID, key halves, PID, granted state and lock mode. Hash collisions may over-serialize but cannot grant authority because full namespace/owner/incarnation are also compared. Lock order: original session owner lock where required, handover lock, then namespace row. Rooted full/incremental readers take shared handover before reading the root; writers additionally lock the row. Acquire/release/migration/rotation/GC take exclusive handover before the row. This ordering covers catalog/inspection reads that observe rooted projections too.

The common rooted worker guard requires **all**: exact transaction-local namespace, representation, writer format 3, owner, incarnation, base revision; locked header matches and has an owner; calling PID holds granted handover ShareLock; recorded owner_backend_pid still holds granted original ExclusiveLock. Check before planning and on every node/catalog/projection/namespace write, including final root publication. Expected projection/count updates retain base revision; final root changes base to base+1. Same-PID worker ownership is not required, but the owner's lock is. An exclusive handover lock is not a worker ShareLock.

The explicit alternative administrative predicate requires matching namespace/format/representation/owner/incarnation/base, an allowlisted operation (`bootstrap`, `acquire`, `release`, `migrate_v1`, `rotate_v1`, `gc_v1`), both original session and handover ExclusiveLocks held by the caller, and caller PID equal to recorded owner PID. Every write rechecks. Operation permissions are narrow: acquire/release change ownership header only; migrate/rotate can insert nodes, update protected projections and publish root; GC/rotation can delete only proven-unreachable nodes; no admin node UPDATE or TRUNCATE. Bootstrap validates both locks and new owner context before initial inserts. Acquire validates old header/base under both locks before changing PID/token/incarnation and does not permit data writes under the former context. Pure acquire/release do not advance State revision.

Stored-selector dispatch governs namespace/catalog/node and native/public projection triggers. Snapshot format-2 same-PID semantics remain; format-2 settings cannot downgrade or mutate rooted rows. The named migrate_v1 branch accepts an old snapshot_v2 **or records_v0** row before switching the selector, with current owner PID/token/incarnation/base and both exclusive locks. It can insert new nodes and update catalog count projections before the final root switch. The operation and destination selector are authenticated transaction context, not permission granted by a GUC alone. Old-format retained data cannot be modified by a rooted worker.

Loss of owner lock before planning, between writes, or before final root publication aborts and rolls back. Loss after the last successful fenced write but before COMMIT can allow the old commit; shared handover prevents replacement/release from publishing until it ends. There is no claimed deferred commit-time lock check. Replacement cannot publish an incarnation and then be followed by an old-incarnation commit. Release drains shared holders, clears owner under its own fence, commits, then releases the original lock. Lost commit reply returns uncertainty; a fresh verified load/revision/receipt resolves outcome. Do not replay effects on uncertainty.

The trusted database role can satisfy these predicates; advisory locks/GUCs are concurrency fences, not authentication against a malicious client sharing the role. This is A's explicit authority change, not a new security claim.

### C5 — bounded synchronous worker pool

Add `PostgresStorage::from_clients_v1(owner, workers)` and `from_clients_protected_v1(owner, workers, keyring)`; constructor v1 is new and independent of Storage transition API version. Caller-provided Clients preserve TLS configuration. Require 1–4 worker clients, each distinct from the owner. The convenience `connect_incremental_v1(config)` creates one owner and two workers with NoTls; remote TLS callers use supplied clients. It checks runtime context before connecting and creates/disposes clients on executor OS threads. Add direct Tokio runtime dependency/features and update Cargo.lock only as needed for runtime-context guard/tests.

Move synchronous I/O into dedicated OS threads: one owner executor and one per worker. Queue messages own requests/data and return owned results. No SQL transaction/lazy State/borrowed closure crosses threads; do not reuse `PgSource`'s lifetime transmute for the tree path. The owner executor serializes lifecycle and exclusive administration; workers perform incremental/full reads, full CAS and ordinary transitions under C4. No global database-I/O mutex couples workers. A paused operation in namespace A must not prevent B committing when another worker is free; same-namespace serialization is intentional.

FIFO waiting capacity is exactly 64 requests, in addition to at most N executing requests. Saturation returns an explicit `Overloaded` result before any State mutation. Capacity release handles cancellation/drop and every error; no lost permit, unbounded hidden queue, mutation resubmission or retry-counter reset. FIFO order refers to process-local admission, not order of independent database completions. Preserve existing durable ready/effect cursors regardless of local rejection.

Check `tokio::runtime::Handle::try_current().is_err()` before synchronous client calls on each executor. Constructor invoked in an entered runtime refuses before I/O and returns owner/workers in a recoverable error payload; it must not drop synchronous clients there. Document safe disposal on an OS thread. Ordinary constructors' historical behavior is preserved; new pool constructors carry this stronger refusal contract. Thread shutdown drains accepted in-flight work and returns pending requests as explicit cancellation/closure errors without replay, then disposes clients on their executor threads. Owner release remains distinct from arbitrary adapter drop.

### C6 — protection, migration, rotation and integrity

Extend ProtectionKeyring with node/root sealing methods using XChaCha20-Poly1305 and random 24-byte nonces. Node AAD is the canonical tuple `(new_node_domain, namespace, logical_path, node_kind, node_format, key_slot, digest)`. Check envelope alternatives at SQL level; decrypt and verify digest, complete reference identity, schema/comparator and metadata in Rust. Parent plaintext authenticates child key slots. Equal plaintext at different paths/namespaces/key IDs has distinct rows, even with the same digest.

INSERT conflict always reads the exact full-key existing row, verifies/decrypts it using its own recorded key/AAD, recomputes digest/summaries, and compares canonical plaintext bytes. Equal plaintext reuses an existing envelope even if the proposed random nonce/ciphertext differs. Bad envelope, wrong bytes, missing key, malformed metadata or address mismatch aborts the entire transaction; digest match alone never permits reuse.

Root envelope uses a distinct root domain, namespace, State revision, representation/node/schema format, active key ID, full root reference and exact counters. Owner/incarnation are excluded. Acquisition verifies the root using referenced keys and increments incarnation without changing State revision or root bytes; a different configured active key does not force resealing. Missing required root key refuses. Regular commits can retain reachable old-key nodes; only explicit rotation promises retirement. Full load/audit and migration/rotation verify every reachable retained value; selected transaction paths are freshly verified. Superuser alteration of unrelated history may be detected only when read or audited, as explicitly approved in A. Neither a warm cache nor a digest-only row lookup bypasses verification.

`migrate_namespace_v1(namespace, owner)` is explicit and exclusive. Read and validate the full old snapshot/legacy record State and artifacts, enforce source/index/receipt/disposal checks and exact quotas, and refuse active or blocked runs, unresolved intents/effects, outstanding waits/children, queued destinations or other pending work. Build and audit the new root; atomically publish selector/root/projections and clear obsolete legacy payloads. Refusal/rollback preserves the old selector and all bytes. Do not delete legacy State data before its replacement is validated. Converting legacy records adds no exemption for their lack of historical cryptographic proofs: validate all available current data, and make no retrospective integrity claim. Fresh opted-in namespaces can bootstrap tree_v1 directly.

`reencrypt_namespace` remains a single explicit atomic operation under exclusive handover and row lock. Walk and verify all reachable nodes, artifacts, catalog and auxiliary protected values. Rebuild bottom-up under the active key (child key-slot changes can change parent digests), verify complete materialized State and exact totals, reseal root and retained values. The proposed final root supplies a verified complete reachability set. Only after that proof may fenced gc_v1/rotate_v1 delete namespace nodes outside the set, including unreachable old-key rows from earlier history; root publishes last. Ordinary UPDATE/DELETE/TRUNCATE and admin UPDATE/TRUNCATE remain forbidden. Reachable corruption/missing keys refuse; corrupt unreachable rows can be removed only after proven unreachable. Rollback restores inserts, reseals, deletions and old root together.

After successful rotation every retained namespace reference/protected value uses the active key and no old-key node rows remain; cold load and recreation of a previously seen node must work with only that key. This does not release keys needed by another namespace, other stored values, backups or WAL. No prior root is retained as readable history. Initial ordinary commits may leave unreachable immutable rows until explicit GC/rotation; measure physical growth and disclose that no physical-storage bound is provided. Logical retention continues preserving unsettled obligations, tombstones and complete artifact references.
