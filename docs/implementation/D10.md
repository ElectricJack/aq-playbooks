# D10 — bounded transition persistence (PB-04)

Status: implemented as opt-in PostgreSQL writer format 3. The named cost test
passes. The PB-02 matrix on pinned PostgreSQL 17.11 meets the required
history ratio (transition p95 at history 512 ≤ 2× history 0) in every measured
transition cell. The 25 ms admission and 100 ms dispatch absolute targets are
**not** met on this host; that is reported below as a limit.

Plan: review `rev-wise-rapids`, approved at revision 4
(`projects/aq-playbooks/plans/2026-11-02-d10-bounded-transition-representation-quota-proof-and-tdd-pl.md`;
repository copy `docs/superpowers/plans/2026-11-02-d10-bounded-transition-persistence.md`).
Deviations from the plan's representation are listed under *Limits*.

## What changed

- **Shared planner and capability** (runner):
  - `Storage::transition_v1` and `Storage::transition_v1_support`
    (`crates/aq-playbooks-runner/src/storage.rs:69-80`). Both default to
    `Unsupported`/`false`, so every existing backend keeps the complete
    `load`/`compare_and_swap` path. `load` and `compare_and_swap` remain
    complete-State operations.
  - The Engine runs the **same** transition closure over either a complete
    State or a State whose 33 retained-history containers are lazy
    (`crates/aq-playbooks-runner/src/transition.rs:85`, `lazy_fields`).
  - Lazy keyed containers live in `crates/aq-playbooks-runner/src/lazy.rs`:
    - `LazyMap`, `LazySet` and `LazySeq` use typed physical keys (`TreeKey`)
      whose order is the schema comparator.
    - A container that needs a full view records an explicit fallback; it
      never returns a partial State.
  - `State.budgets` became a `LazyMap`
    (`crates/aq-playbooks-runner/src/lib.rs:278`). While it was a plain map,
    the per-transition header grew from 15 KB to 49 KB at history 512. The
    cost test caught this.
- **Exact maintained accounting.** The planner updates `Accounting`, which
  holds the header length, per-field container stats and queued destinations
  (`transition.rs:229`), from the touched records only. Quota checks
  (`check_quota`, `transition.rs:50`) use those counts, which equal
  `quota_counts(&State)` on the assembled state. The cost test asserts that
  equality.
- **In-memory record backend.** `RecordStorage` (`transition.rs:323`) is the
  deterministic reference implementation, with value-free counters in
  `RecordStats`.
- **PostgreSQL writer format 3:**
  - Code: `crates/aq-playbooks-postgres/src/records.rs`,
    `migrations/0005_transition_records.sql`, and
    `PostgresStorage::connect_records`/`from_client_records`
    (`src/lib.rs:128-135`).
  - **Storage layout.**
    - The namespace row holds the State header (artifacts stripped) and its
      accounting.
    - Each container record is one `state_records` row, keyed
      `(namespace, field, order-preserving sort_key)`.
    - A transition binds the lazy containers to the row-locked transaction,
      runs the plan and writes only the touched records. The revision bump
      happens in the same transaction.
    - Plans that remove retained history, change artifact or catalog inputs,
      or report a fallback commit through the complete path instead
      (`heavy`).
  - **Writer guards.**
    - The format check allows 2 or 3, and a format downgrade is refused.
    - A format-3 row stores the snapshot `'null'`, which every earlier
      decoder refuses.
    - The record trigger requires the writer namespace and format settings.
  - **Counters.** `transition_stats()`/`reset_transition_stats()`
    (`records.rs:578`) count incremental, heavy and unchanged commits, full
    loads, full commits, record reads and writes, and fallbacks.
  - The SQL `query` path reads ready, deadline and other index answers from
    records for format 3 (`lib.rs:315`).
- **Benchmarks:**
  - `examples/operating_envelope.rs`:
    - The `Measured<S>` wrapper forwards `transition_v1` (timed as
      `transition_us`) and `transition_v1_support`.
    - `pg()` uses `connect_records` and asserts support for every cell's
      namespace.
    - A preflight (below) runs before any timed cell.
    - Counters are reset after seeding and preflight. Every row emits
      `transition_work` and `bounded`. Admit, event and pending cells assert
      `incremental == samples`, zero heavy/full-load/full-commit operations
      and zero fallbacks.
    - Configuration version is 3. Fixture, sample counts, histories and
      scenarios are unchanged.
  - `examples/admission_benchmark.rs` uses `connect_records` and reports the
    same counters.
  - The script `scripts/benchmark-envelope.sh` is unchanged.

## Deterministic cost proof

The test is `crates/aq-playbooks-postgres/tests/transition_cost.rs`.

**Setup.**
- The five-artifact PB-02 fixture (return-a/b/c, child-wait, parent
  OwnedAsync) is grown to histories 0/32/128/512.
- At each history it is seeded into the record backend and into a full-State
  `MemoryStorage` reference.

**Per operation.** Each sample runs an admit, an event and a dispatch on both
stores, then checks:
- equal results and revisions;
- equal complete serialized State;
- on the final sample, equal canonical bytes and maintained accounting equal
  to `quota_counts` of the reference;
- zero full loads, zero full commits and zero fallbacks, with a bounded
  transition performed.

**Across histories.**
- Record reads per operation are exactly equal to history 0.
- Header bytes are within 16 bytes of history 0. Only counter digits vary.

**Observed record reads per operation.** These are identical at every history.

| Operation | Record reads (maximum) |
| --- | --- |
| Admit | 13 |
| Event | 7 |
| Dispatch | 20 |

The header is about 14.9 KB at every history.

**PostgreSQL variant.** The same proof runs against PostgreSQL format 3 under
`postgres-tests` (`transition_cost_flat_with_history_postgres`, histories
0/32 with 4 samples). Heavy-path commits count as full commits there.

### Absolute targets (reported limits)

- **25 ms admission p95 is not met.**
  - Event p95 is 31.4–112.9 ms.
  - Pending-child cells: 0 and 128 pass, 8 and 32 miss.
  - The p50 is about 24–29 ms. One durable commit on this host costs about as
    much as the whole budget.
  - The in-process closure p95 is 2.7–15.5 ms. It includes lazy record
    fetches over SQL and is not the full-state pure-closure figure of PB-02.
- **100 ms dispatch p95 is not met at every cell.**
  - Ready 6: 104.4 ms at h=0 and 202.1 ms at h=32 miss; h=128 is 117.8 ms
    (miss); h=512 is 76.5 ms (pass).
  - Ready 24: 69.4 ms at h=512 passes; 177.5, 133.4 and 121.6 ms at lower
    histories miss.
  - A dispatch visits about 20 records with one SQL round trip each, plus the
    commit.
- These are limits, not task failures under the acceptance criteria. Batching
  record reads (one round trip per container page) and commit grouping are
  follow-up work.

## Limits and follow-ups

**Representation.**
- The plan's authenticated Merkle node tree (plan Task 3) is **not**
  implemented. Format 3 uses keyed plaintext records under the namespace row
  lock with exact maintained accounting. Untouched-history tampering is not
  detected by a root hash.
- Protected namespaces stay on format 2. Plan Task 5 (protected migration and
  atomic rotation of record rows) is not done, and there is no in-place
  migration of an existing namespace. A fresh `connect_records` namespace
  returns `Unsupported` until its first full commit stores format 3.

**Paths that stay O(state).**
- `inspect`, `load`, full CAS and heavy commits. Heavy covers retained-history
  removal by GC or retention, artifact and catalog changes, and plans that
  fall back.
- The remaining runner fallbacks are `fail_run`, epoch retirement and GC
  disposal.
- The GC cutoff is evaluated on the light path only when the GC clock changes.

**SQL and PostgreSQL.**
- The format-2 SQL `runtime_index`/`inspection_rows` projections are not
  maintained for format 3. Indexed queries read records instead.
- The record trigger checks the writer namespace and format settings only.
  Plan Task 4's owner-PID, incarnation, administrative-operation fences and
  bounded worker pool are not implemented.
- Old writers are fenced only by the downgrade refusal and the `'null'`
  snapshot.

**Scope.**
- Out of scope, unchanged: the D4 host catalog, aq-server, the J3 deployed
  measurement, any 500-agent claim, active-run migration, unresolved-work
  eviction and quota widening.
